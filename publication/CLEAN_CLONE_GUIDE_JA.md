# クリーンクローン検証ガイド

更新日: 2026-08-06  
対象: ChromaMatter — AI Model Print Studio の公開候補リポジトリ

## クリーンクローンとは

クローンは、GitHub などに置いたリポジトリを新しいフォルダーへ複製することです。

クリーンクローン検証は、いま開発に使っているフォルダーをそのまま動かすのではなく、何も入っていない新しい場所へ「公開予定のファイルだけ」を取得し、そこからセットアップ、テスト、起動、ビルドをやり直す確認です。

言い換えると、別の人の PC に渡した状態を自分の PC 上で再現する試験です。

## なぜ必要か

開発中の PC では、次のような隠れた依存が偶然そろっているため、公開物に不足があっても動いてしまいます。

- Downloads や Desktop にだけ存在するモデル
- 個人の絶対パス
- 以前インストールした Python パッケージ
- 公開対象外の DLL、EXE、pyc
- 手作業でコピーしたモデルデータやアイコン
- Git で追跡されていない設定ファイル
- 古いビルドフォルダーに残ったファイル

クリーンクローンで動けば、「作者の現在の PC だけで動く」状態から一歩進み、公開物だけで再現できることを確認できます。

## 1. 公開候補の範囲を先に固定する

初回公開では、現在の作業フォルダー全体を公開対象にしません。公開候補の中心は、由来を説明できる現在の実装である **source/fixed_app** とします。

公開候補の例:

    ChromaMatter/
      source/
        fixed_app/
      tests/
      tooling/
      licenses/
      publication/
      README.md
      PROVENANCE.md
      LICENSE
      requirements または lock file

公開候補から除外する例:

    source/recovered_pyc/
    source/original_icon_source.exe
    old_exe/
    release_stage/
    build_output/
    dist/
    validation_private/
    private_models/
    temporary_meshes/

フォルダー名だけでなく、同じ内容のコピーや ZIP 内の重複も除外します。

## 2. 実行前に作るもの

- 公開予定ファイルだけを含む Git ブランチまたはローカル候補
- Python の対応バージョンを明記したセットアップ手順
- 正確な依存関係の版を固定したファイル
- テストコマンド
- 起動コマンド
- ソース配布用のファイル一覧
- バイナリ配布を試す場合は、別のバイナリ監査一覧
- 合成サンプルを生成する手順

実モデル、元画像、3MF は再現用データに使いません。合成サンプルだけで公開テストが完了できるようにします。

## 3. クリーンクローンの手順

以下は公開直前に実施する受入手順です。まだ GitHub に公開する必要はなく、ローカルの非公開リポジトリや bundle でも同じ考え方で確認できます。

### 手順 A: 空の場所へ取得

1. 開発フォルダーの外に、新しい空の検証フォルダーを作る。
2. 公開候補を Git clone、git bundle、または公開候補 ZIP から取得する。
3. 開発フォルダーから追加コピーしない。
4. 新しいフォルダーに Git で追跡されていないファイルがないことを確認する。

### 手順 B: 新しい Python 環境

1. README に記載した Python バージョンだけを使用する。
2. 新しい仮想環境を作成する。
3. 固定した依存関係ファイルからインストールする。
4. PC に既にある開発用 site-packages を参照していないことを確認する。
5. インストールされた正確なパッケージ一覧を保存する。

### 手順 C: ソースから検証

1. 合成サンプルを公開手順どおりに生成する。
2. 自動テストをすべて実行する。
3. ChromaMatter を起動する。
4. 合成 OBJ を読み込む。
5. 色変換、マニュアル修正、分割、3MF 出力を確認する。
6. 開発フォルダーや個人フォルダーを参照していないことを確認する。

### 手順 D: パッケージ内容の確認

ソース ZIP または EXE 候補を別の空フォルダーへ展開し、一覧を保存します。公開対象外ファイルが一つでも含まれた場合は、その候補を破棄して作り直します。

## 4. 個人パスと個人データの検索

公開候補のルートで、次のような検索を行います。山括弧の部分は検証時の値に置き換えます。

~~~powershell
$windowsUsersRoot = Join-Path $env:SystemDrive 'Users'
$unixUsersRoot = '/' + 'Users'
rg -n -F -e $windowsUsersRoot -e $unixUsersRoot -e '/home' -e 'Downloads' -e 'Desktop' .
rg -n -S "<Windowsユーザー名>|<実名>|<メールアドレス>" .
rg -n -S "api[_-]?key|secret|token|password" .
rg --files -g "*.pyc" -g "*.pyo" -g "*.dmp" -g "*.log" -g "*.tmp"
rg --files | rg -i "recovered_pyc|original_icon_source|release_stage|build_output|private|backup"
~~~

注意:

- 検索結果がゼロであることだけを合格条件にしません。README の例示パスなど、意図した記述は人間が確認します。
- バイナリ、ZIP、3MF、画像にも個人データが含まれる可能性があります。テキスト検索に加えて展開内容とメタデータを確認します。
- Git は削除済みファイルを履歴に保持します。過去に公開対象外ファイルをコミットした場合、公開前に履歴から除去した新しい履歴を作り、除去を検証します。
- 秘密情報を一度でも公開先へ push した場合、履歴削除だけでなくキーの失効と再発行が必要です。

## 5. 必ず除外を確認する項目

- [ ] source/recovered_pyc がない。
- [ ] source/original_icon_source.exe がない。
- [ ] 旧 EXE、旧 ZIP、旧アイコンがない。
- [ ] __pycache__、pyc、クラッシュダンプがない。
- [ ] 実モデル、元画像、出力 3MF、動画素材がない。
- [ ] 一時 STL と内部診断用メッシュがない。
- [ ] Downloads、Desktop、個人ユーザー名への絶対参照がない。
- [ ] API キー、トークン、メールアドレスがない。
- [ ] テスト結果に個人パスが保存されていない。
- [ ] ビルド成果物に不要な第三者素材がない。

これらは .gitignore だけに頼りません。公開候補に実際に含まれる追跡ファイルと、生成した ZIP・EXE の内容を確認します。

## 6. ソースのみ公開の合格条件

- [ ] 空のフォルダーからセットアップできる。
- [ ] 公開手順だけで合成サンプルを生成できる。
- [ ] 自動テストが成功する。
- [ ] ChromaMatter が起動する。
- [ ] 合成サンプルから 3MF を出力できる。
- [ ] 個人の開発フォルダーがなくても動く。
- [ ] LICENSE、PROVENANCE、第三者ライセンス一覧が含まれる。
- [ ] 旧 EXE、recovered_pyc、旧アイコン、実モデルが含まれない。
- [ ] README に未検証事項と既知の制限が明記される。

## 7. EXE 公開には別の合格条件が必要

ソースのクリーンクローンに成功しても、EXE 配布の許可にはなりません。EXE は追加で次を満たす必要があります。

- [ ] 最終 EXE へ実際に同梱された全依存関係を棚卸しした。
- [ ] TetGen、PyMeshLab、Qt、GEOS などの配布条件を確認した。
- [ ] 対応ソース、ビルドスクリプト、パッチ、正確な版を保存した。
- [ ] ライセンス全文と著作権表示を同梱した。
- [ ] Qt の採用ライセンスと置換・再リンク方法を確認した。
- [ ] 新しい PC または仮想マシンで EXE を起動・操作した。
- [ ] EXE から個人パス、実モデル、旧素材が出てこない。

この監査が完了するまでは、公開物をソースのみに限定します。

## 8. 検証記録の残し方

公開時には次を記録します。

- 検証日
- 検証したコミット ID
- Windows と Python の版
- インストールした依存関係一覧
- 実行したコマンド
- テスト結果
- 生成した配布物の SHA-256
- 失敗と修正内容
- 検証者

クリーンクローン成功とは、「いまの開発フォルダーで動いた」ことではなく、「公開予定ファイルだけを新しい場所へ取得し、書かれた手順だけで第三者が再現できる状態になった」ことです。
